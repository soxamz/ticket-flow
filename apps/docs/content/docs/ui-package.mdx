## Overview

`@repo/ui` is the shared component and styling layer for TicketFlow.

- Reused by `apps/web` and `apps/docs`
- Built around shadcn-style components
- Provides theme tokens, utility helpers, and composed UI primitives

## Core Principles

1. Keep visual primitives centralized.
2. Reuse typed components across apps.
3. Keep styling token-driven (`--background`, `--primary`, etc.).
4. Prefer composition (`Card`, `Field`, `Alert`, `Table`) over one-off markup.

## Common Imports

```tsx
import { Button } from "@repo/ui/components/button";
import { Card, CardContent, CardHeader, CardTitle } from "@repo/ui/components/card";
import { Input } from "@repo/ui/components/input";
import { cn } from "@repo/ui/lib/utils";
```

## Theming

Global CSS tokens live in:

- `packages/ui/src/styles/globals.css`

The web app enables runtime light/dark mode via `next-themes` in:

- `apps/web/src/components/theme-provider.tsx`
- `apps/web/src/components/mode-toggle.tsx`

## Component Categories

### Form and input

- `field`, `form`, `input`, `select`, `textarea`

### Data display

- `card`, `table`, `badge`, `avatar`, `skeleton`, `empty`

### Navigation and overlays

- `dropdown-menu`, `sheet`, `dialog`, `tooltip`

### Feedback

- `alert`, `sonner`, progress/loading states

## Usage in TicketFlow Features

1. Auth pages use `Card`, `Field`, and `ShimmerButton`.
2. Dashboard pages use `PageHeader`, `Card`, `Empty`, and `Alert`.
3. Booking flow uses `Card`, `Alert`, `Skeleton`, and action buttons.
4. Admin views use `Table`, `Badge`, `Card`, and forms.

## Adding Components

From `packages/ui`, add new primitives with shadcn tooling and keep exports aligned:

```tsx
cd packages/ui
bunx shadcn@latest add dialog
```

## Transpile Configuration

Apps that consume `@repo/ui` must transpile it in Next config:

```ts
const nextConfig = {
  transpilePackages: ["@repo/ui"],
};
```

This keeps package code reusable without a separate build step.

```tsx
import {
  Card,
  CardHeader,
  CardTitle,
  CardDescription,
  CardContent,
  CardFooter,
} from "@repo/ui/components/card";
import { Button } from "@repo/ui/components/button";

export function Example() {
  return (
    <Card>
      <CardHeader>
        <CardTitle>Card Title</CardTitle>
        <CardDescription>A short description of the card.</CardDescription>
      </CardHeader>
      <CardContent>
        <p>Card body content goes here.</p>
      </CardContent>
      <CardFooter>
        <Button>Action</Button>
      </CardFooter>
    </Card>
  );
}
```

## Utilities

### `cn()` — Class Name Merger

Combines Tailwind CSS classes with proper conflict resolution:

```tsx
import { cn } from "@repo/ui/lib/utils";

// Merges classes, resolving conflicts
cn("px-4 py-2", "px-8"); // → "py-2 px-8"
cn("text-red-500", condition && "text-blue-500");
```

## Adding New Components

Use the shadcn CLI from the `packages/ui` directory:

```bash
cd packages/ui
bunx shadcn@latest add dialog
```

Components are installed into `src/components/` and automatically exported via the package's `exports` field.

## How It Works

The UI package uses a **JIT (Just-In-Time) compilation** strategy — components are compiled by the consuming app's bundler, not pre-built. This is configured via `transpilePackages` in each app's `next.config.ts`:

```ts
// apps/web/next.config.ts
const nextConfig: NextConfig = {
  transpilePackages: ["@repo/ui"],
};
```

The CSS theme tokens are defined in `packages/ui/src/styles/globals.css` and imported by each app's root layout.
